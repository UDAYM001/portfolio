I build tools that delete repetitive work. A process that took a person an afternoon — filling a thousand PDFs, reconciling two spreadsheets, sending a mail run, clicking through the same five screens — becomes a script that finishes before you look up.

My day-to-day is Python and Playwright for the automation spine, C# and .NET WinForms when the tool has to live on a Windows desktop, and LLM APIs where a rule-based step would be brittle: reading messy documents, classifying free text, drafting content that a human then approves.

Prompt engineering is the part people underrate. A prompt is an interface contract — it needs the same care as a function signature: constrained inputs, a defined output shape, and a fallback when the model is unsure.

04 — Process

How a manual task
becomes a tool.

Same three moves every time. The order matters more than the tooling.

Watch the real work

I sit with the actual clicks and files first. Most "complex" processes turn out to be four decisions wrapped in a lot of copying — and the edge cases are where the whole build lives.

Automate the deterministic spine

Everything with a fixed rule gets scripted: file handling, form filling, navigation, validation. Deterministic code is cheap to test and never hallucinates, so it carries as much of the load as possible.

Put the model where judgment is

Only the fuzzy steps go to an LLM — reading an unstructured document, classifying intent, drafting text. Constrained output, a validation pass, and a human checkpoint where being wrong would be expensive.
